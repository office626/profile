# 土屋俊博 ブランディングサイト — 運用ガイド

## 今回のサイト
6つの分野別LP、13の依頼メニュー、48件の公開実績、プロフィール、研究・発信、相談フォームを統合しました。各メニューに成果物・期間・費用目安を記載し、相談時にメニューと参考実績を引き継ぎます。問い合わせは既存と同じ FormSubmit 宛てです。実際の送信テストは行っていません。受信先の有効化状態は最初の実問い合わせ時に確認してください。

元情報は office626.com の公開内容と office626/profile の公開データです。主な経歴・料金・実績の原本更新日は2026年8月29日です。本人写真も既存サイトのものを引き継いでいます。新たな実績や成果の数字は作っていません。

## 毎週の流れ
毎週金曜19時（日本時間）に専用フォルダを確認します。Codexの定期実行にはこのパソコンとCodexの実行環境が利用できる必要があります。

1. `inbox/公開用資料` に、紹介したい資料のコピーを置く。
2. `inbox/活動日報` に、その週に実際に行った仕事をテキスト・Markdownで記録する。
3. 定期実行が変更を見つけ、紹介文の候補をこのタスクに提示する。
4. 内容と資料の公開範囲を確認して返信する。
5. 確認済みのデータをGitHubへ反映する。公開ブランチへ取り込まれた内容からGitHub Actionsがページを再生成する。

指定フォルダ以外のPCファイル・ブラウザ履歴・メールを横断取得する設定にはしていません。追加の取得元は、場所と対象を指定してから接続できます。

## 公開前に確認すること
紹介文と、元ファイルの公開は別々に指定できます。紹介文だけの公開も可能です。顧客名・参加者名・社内情報などが入る資料は、公開用に編集したコピーを使ってください。PDFやOfficeファイルの本文を機械的に要約して公開する機能は設けておらず、定期実行で候補を整理します。マクロ等は実行しません。

元ファイルが変更されると、それまでの承認は無効になります。ファイルの内容を識別するSHA-256を照合し、再確認するまで公開を止めます。紹介文の承認だけで元ファイルが公開されることはありません。取り下げは確認用データのstatusをwithdrawnにします。ただし、一度公開されたGit履歴やダウンロード済みコピーは、サイトから取り下げても消えません。

## 更新の正本
- 経歴・所属・料金・メニュー：既存リポジトリの `profile.yaml`
- 既存実績：既存リポジトリの `portfolio.yaml`
- 確認済みの追加実績：`brand/content/collected-cases.json`
- 確認済み活動記録：`brand/content/activities.json`
- 公開資料：`brand/public/files/`

GitHub ActionsがYAMLから公開用JSONを生成します。非公開指定の連絡先は取り込みません。JSONからLP・実績詳細・検索・関連実績を自動生成するので、各ページを個別に手直しする必要はありません。

## サイトの確認と切り替え
Sitesの確認用URLは本人限定です。GitHubの変更案を確認してmainへ取り込むと、GitHub Pages側が更新される構成です。既存の `portfolio.html` は新しい実績一覧へ転送します。

office626.com は現在Google Sitesで配信されています。同じ独自ドメインに切り替えるには、ドメイン側の管理権限が必要です。GitHub PagesのCustom domain設定とDNSの切り替えは別途行ってください。独自ドメインへ切り替える場合は、公開ワークフローのNEXT_PUBLIC_BASE_PATHを空にし、SITE_ORIGINを https://www.office626.com に変更します。既存のGoogle Sites内ページは、旧パスを新LPへ対応づけて移行します。DNSを変更する前に代表ページと問い合わせ先を確認してください。

## 実行担当者向け
通常のローカル確認：`npm ci` → `npm run dev`
収集：`node scripts/collect.mjs .local/config.json`
確認済みデータの反映：`node scripts/publish-content.mjs .local/config.json`
検証：`npm test` と `npx tsc --noEmit`
GitHub Pages用：`npm run build:pages`（出力はdist/client）
Sites用：`npm run build`

`.local` と `inbox` はGitの追跡対象外です。実績の元ファイル・未確認日報・承認用の元パスはGitHubへ送信しません。`scripts/config.example.json` を `.local/config.json` にコピーしてパスを設定します。承認用JSONの形式は `scripts/approval.example.json` を参照してください。

公開用の生成では vinext 1.0.0-beta.5 のbasePath・末尾スラッシュの事前生成問題に、バージョン固定の最小修正を適用しています。依存関係を更新するときは `scripts/patch-prerender.mjs` を検証してください。

同期スクリプトはoffice626/profileと設定されたブランチ以外に送信しません。作業中の変更、競合、ファイル内容の変更がある場合は停止します。GitHubへの書込み認証はGitHub CLIの既存ログインを使い、トークンをソースに保存しません。
